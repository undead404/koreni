# Інтеграція зовнішнього сайту з «Кармою» Генеалогічного навігатора

Цей документ — для розробників сторонніх сервісів, які хочуть, щоб корисні дії їхніх
користувачів додавали бали карми на сайті [uagenealogy.com](https://www.uagenealogy.com).

## Як це працює (коротко)

- Модель — **push**: ваш сайт сам надсилає нам дані, ми вас **не опитуємо**.
- Передаєте **поточний підсумок балів** користувача (накопичувальне число), а не окремі події.
  Ми нараховуємо лише **приріст** відносно попереднього значення.
- **Бали ніколи не зменшуються.** Якщо підсумок впав — ми просто нічого не міняємо.
- Повторні/дублюючі надсилання безпечні: приріст буде 0.

Базовий URL усіх запитів:

```
https://www.uagenealogy.com
```

## Що потрібно отримати від адміністрації

1. **`code`** вашого сайту (slug, напр. `inventarium`).
2. **`identity_type`** — як ми звіряємо користувачів:
   - `email` — за email-адресою;
   - `telegram` — за числовим Telegram ID.
3. **Push-токен** (`Bearer`-токен). Видається в адмінці один раз; зберігайте таємно.
   Якщо токен скомпрометовано — адмін згенерує новий (старий перестане діяти).

Усі запити авторизуються заголовком:

```
Authorization: Bearer <ВАШ_ТОКЕН>
```

## 1. Передача балів — `POST /api/karma/ingest`

Викликайте періодично (рекомендовано — **раз на добу, одним батчем** на всіх користувачів).

### Запит

```http
POST /api/karma/ingest
Authorization: Bearer <ВАШ_ТОКЕН>
Content-Type: application/json
```

```json
{
  "accounts": [
    { "login": "ivan@example.com", "total": 130 },
    { "login": "olena@example.com", "total": 42 }
  ]
}
```

- `login` — ідентифікатор користувача **на вашому сайті**:
  - для `identity_type = email` — email (регістр не важливий, ми приводимо до нижнього);
  - для `identity_type = telegram` — числовий Telegram ID у вигляді рядка.
- `total` — **поточний сумарний бал** користувача у вас (ціле число, накопичувальне).

### Відповідь

```json
{
  "synced": 2,
  "awarded": 30,
  "unknown": ["olena@example.com"]
}
```

- `synced` — скільки акаунтів оброблено;
- `awarded` — скільки балів карми сумарно нараховано цим запитом;
- `unknown` — `login`-и, яких ще **немає привʼязки** на нашому боці (користувач не привʼязав
  ваш сайт у себе в кармі). Це не помилка — просто надішлете їх знову наступного разу.

### Як рахується приріст

```
приріст_карми = (total − попередній_total) × коефіцієнт_сайту
```

Коефіцієнт задає адмін (за замовчуванням 1). Ви завжди надсилаєте **сирий підсумок**;
конвертацію робимо ми.

### Приклад (curl)

```bash
curl -X POST https://www.uagenealogy.com/api/karma/ingest \
  -H "Authorization: Bearer $KARMA_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"accounts":[{"login":"ivan@example.com","total":130}]}'
```

## 2. Привʼязка акаунтів (`POST /api/karma/link-redeem`)

Щоб бали користувача потрапляли куди треба, він має **звʼязати** ваш акаунт зі своїм
профілем у нас. Привʼязка **єдина для всіх сайтів** і базується на одноразовому коді,
який **гасить ваш сайт** — цим він підтверджує, що користувач реально ваш (адже він у вас
залогінений). Email ми самі не перевіряємо — за це ручається ваш сайт.

### Загальний флоу

1. Користувач у нас (`/karma/connections`) натискає «Привʼязати» → ми показуємо йому
   одноразовий код, напр. `AB12CD34EF` (діє 15 хв).
2. Користувач, **уже залогінений у вас**, передає цей код вашому сайту:
   - **web/email-сайт** — вводить код на вашій сторінці привʼязки (її URL ви вказуєте нам);
   - **telegram-бот** — надсилає боту команду `<команда> AB12CD34EF` (команду ви задаєте; за замовчуванням `/link`).
3. Ваш сайт викликає наш ендпоінт, передаючи код і **підтверджений ідентифікатор** користувача:

```http
POST /api/karma/link-redeem
Authorization: Bearer <ВАШ_ТОКЕН>
Content-Type: application/json
```

```json
{ "code": "AB12CD34EF", "login": "ivan@example.com", "total": 130 }
```

- `login` — те, чим ви ідентифікуєте користувача і чим потім надсилатимете бали:
  - для `identity_type = email` — email (приводимо до нижнього регістру);
  - для `identity_type = telegram` — числовий Telegram ID (рядком).
- `total` _(необовʼязково)_ — поточний підсумок балів користувача. Якщо передасте —
  ми нарахуємо їх **одразу під час привʼязки**, не чекаючи нічної синхронізації.

4. Відповідь `{ "ok": true, "awarded": 130 }` — привʼязку створено (`awarded` — скільки
   карми нараховано одразу). Далі надсилайте бали через `/api/karma/ingest` із тим самим `login`.

Помилки погашення:

- `404 { "error": "invalid_or_expired" }` — коду немає або він прострочений (15 хв);
- `409 { "error": "already_linked" }` — цей `login` уже привʼязаний іншим користувачем.

> Telegram: команда **не `/start`** (її задає адмін, типово `/link`), тому deep-link
> `?start=` тут не використовується — користувач відкриває бота й надсилає `<команда> <КОД>`.

### Приклад (curl)

```bash
curl -X POST https://www.uagenealogy.com/api/karma/link-redeem \
  -H "Authorization: Bearer $KARMA_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"code":"AB12CD34EF","login":"ivan@example.com"}'
```

### Що треба реалізувати на вашому боці

- **web/email-сайт:** сторінка для залогіненого користувача, де він вводить код, а ви
  викликаєте `link-redeem` з його email. URL цієї сторінки повідомте адміну.
- **telegram-бот:** обробник команди `<команда> <КОД>`, який бере Telegram ID
  відправника і викликає `link-redeem`. Юзернейм бота й команду повідомте адміну.

## 3. Публічне читання карми — `GET/POST /api/karma/lookup`

Публічний ендпоінт (без токена) для відображення карми користувача у вашому сервісі —
напр. бейдж «N балів карми». Повертає **карму саме з вашого сервісу** і **повні бали**.

### GET (зручно для одного/кількох)

```
GET /api/karma/lookup?service=<slug>&user=<login>
GET /api/karma/lookup?service=<slug>&user=<login1>&user=<login2>
GET /api/karma/lookup?service=<slug>&users=login1,login2
```

### POST (для великих списків)

```json
POST /api/karma/lookup
{ "service": "<slug>", "users": ["login1", "login2"] }
```

- `service` — код (slug) вашого сервісу.
- `user`/`users` — логіни на вашому боці (email або telegram_id), як і в `ingest`.

### Відповідь

```json
{
  "service": "inventarium",
  "name": "Інвентаріум",
  "results": [
    {
      "user": "ivan@example.com",
      "found": true,
      "serviceKarma": 381,
      "totalKarma": 2487
    },
    {
      "user": "unknown@x.com",
      "found": false,
      "serviceKarma": 0,
      "totalKarma": 0
    }
  ]
}
```

- `serviceKarma` — карма, нарахована саме за ваш сервіс (`бали × коефіцієнт`, округлено).
- `totalKarma` — повні бали карми користувача.
- `found: false` — цей логін ще не привʼязаний у Навігаторі.

Підтримує CORS (`*`), тож можна викликати і з браузера. Токен не потрібен.

## Коди помилок

| Код   | Значення                                          |
| ----- | ------------------------------------------------- |
| `200` | Успіх                                             |
| `400` | Невалідний JSON / бракує полів / не той тип сайту |
| `401` | Немає або невірний токен                          |
| `404` | (link-redeem) код недійсний або прострочений      |
| `409` | (link-redeem) Telegram ID уже привʼязаний іншим   |
| `500` | Сервіс тимчасово не налаштований                  |

## Рекомендації

- Надсилайте **сумарний підсумок**, а не дельти.
- Один батч-запит на всіх користувачів раз на добу — достатньо.
- Не зменшуйте `total` штучно — зниження все одно ігнорується.
- Зберігайте токен у секретах (env), не в коді репозиторію.
- `unknown`-логіни не вважайте помилкою — користувач міг ще не привʼязати акаунт.

## Питання

Звертайтеся до адміністрації Генеалогічного навігатора через форму зворотного звʼязку на сайті.

## Операційне налаштування Koreni

Koreni має дві ролі в інтеграції:

- сервер зберігає стан привʼязки акаунта (`karma_linked_at`) і після згоди віддає
  привʼязані адреси через `GET /api/karma/linked-users`;
- щоденний GitHub Actions workflow читає файли-джерела репозиторію, обчислює поточні
  накопичувальні підсумки та надсилає один batch до Navigator.

### Змінні середовища

У локальних `.env` файлах використовуйте такі змінні (шаблони є в корені та в
`src/server/.env.example`):

| Змінна                 | Призначення                                                               |
| ---------------------- | ------------------------------------------------------------------------- |
| `KARMA_APP_TOKEN`      | Bearer-токен Navigator для `/api/karma/ingest` і `/api/karma/link-redeem` |
| `KARMA_INTERNAL_TOKEN` | Bearer-токен для захищеного Koreni endpoint `GET /api/karma/linked-users` |
| `NAVIGATOR_BASE_URL`   | Базова URL Navigator; за замовчуванням `https://www.uagenealogy.com`      |
| `SITE`                 | Публічна URL Koreni, яку використовує scheduled workflow                  |

Значення токенів не можна додавати до Git, логів, клієнтського bundle чи telemetry.
Зберігайте їх лише в локальному `.env` (який не комітиться) або в GitHub repository
Secrets. `GET /api/karma/linked-users` відхиляє запити без точного
`Authorization: Bearer <KARMA_INTERNAL_TOKEN>`.

### Щоденна синхронізація

`.github/workflows/karma-daily-sync.yml` запускає `yarn karma:push` щодня о 03:00 UTC.
У repository Secrets мають бути налаштовані:

- `KARMA_APP_TOKEN` — push-токен Navigator;
- `KARMA_INTERNAL_TOKEN` — внутрішній токен Koreni.

Repository variable `SITE` задається як URL production Koreni у workflow, а
`NAVIGATOR_BASE_URL` має значення `https://www.uagenealogy.com`, якщо не потрібен інший
endpoint. Перед запуском workflow встановлює залежності та обчислює внески зі свіжих
файлів репозиторію, тому не зберігає cursor, delta або інший стан синхронізації.

Якщо запуск завершився помилкою через мережу або HTTP-помилку, наступний запуск
повторно обчислить усі поточні підсумки та синхронізує їх. Повторний batch безпечний:
Navigator нараховує лише позитивну різницю. У stdout виводяться тільки агреговані
лічильники `synced`, `awarded` і `unknown`; адреси, коди, токени та authorization
headers не логуються.
